# Figure 2.5: A convolution worked through

- **type:** diagram (numerical grids)
- **purpose:** Let the reader follow a convolution by hand: one small kernel slides over an image, multiplies and adds at every position, and produces a feature map that lights up where the pattern (here a vertical edge) is; then show max pooling.
- **caption:** Figure 2.5: A convolution worked through. (a) A 5 × 5 image with a vertical boundary between dark pixels (0) and bright pixels (1), and a 3 × 3 vertical-edge kernel. (b) At each of nine positions the kernel's weights are multiplied by the pixels beneath and added; the highlighted window, straddling the boundary, gives 3 × (−1 × 0) + 3 × (0 × 0) + 3 × (+1 × 1) = 3, one term for each column of three pixels. (c) The resulting 3 × 3 feature map: 0 where there is no edge, 3 in the two columns whose windows straddle it. (d) A separate example of 2 × 2 max pooling, which keeps the largest value in each block, shrinking a 4 × 4 map to 2 × 2. The same nine weights are used at every position. Calculation by the author.
- **content:** (all numbers computed by the author; verified by script)
  - Layout: left → right, panels (a) image and kernel, (b) one highlighted window, (c) feature map; panel (d) below or at the far right.
  - **(a) Image, 5 × 5 grid** (row by row, each row identical): `0 0 0 1 1`. Shade cells with 1 light/white, cells with 0 dark grey; print the number in each cell. Label "Image (5 × 5)".
  - **Kernel, 3 × 3 grid** (each row identical): `−1 0 +1`. Label "Kernel (3 × 3): vertical-edge detector".
  - **(b) Highlighted window:** outline on the image the 3 × 3 window covering rows 1–3 and columns 2–4 (counting from 1), i.e. the window whose columns read 0, 0, 1. Next to it the sum: "(−1)×0 ×3 rows + 0×0 ×3 rows + (+1)×1 ×3 rows = 3". Arrow from the window to the corresponding output cell (row 1, column 2) in panel (c).
  - **(c) Feature map, 3 × 3 grid** (each row identical): `0 3 3`. Label "Feature map (3 × 3)". Cells with 3 shaded light to show "edge detected".
  - Footnote-size label under (c): "5 − 3 + 1 = 3 positions per row and column".
  - **(d) Max pooling:** a 4 × 4 grid divided into four 2 × 2 blocks: rows `1 3 0 2` / `4 2 1 0` / `0 1 5 2` / `2 0 3 1`. Arrow to a 2 × 2 grid: rows `4 2` / `2 5`. Label "2 × 2 max pooling (a separate example): keep the largest value in each block"; the grid is a new example, not the feature map of (c). (Blocks: {1,3,4,2} → 4; {0,2,1,0} → 2; {0,1,2,0} → 2; {5,2,3,1} → 5.)
  - Small note at the bottom: "9 weights + 1 bias, reused at every position (a fully connected layer from 25 pixels to 9 outputs would need 225 weights)".
  - Greyscale.
  - Drawn layout: top row image ∗ kernel = feature map, with titles under the grids; the highlighted window (thick outline) is joined to its output cell (thick outline, row 1, column 2) by a curved arrow over the top labelled "multiply and add"; row (b) is the written sum; row (d) pooling below, with the maximum of each block in bold and alternate blocks lightly shaded. The drawing code recomputes the feature map and the pooled values and asserts them.
