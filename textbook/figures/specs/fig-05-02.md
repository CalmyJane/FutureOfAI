# fig-05-02

- **type:** diagram (sequence diagram)
- **purpose:** Show that in function calling the model only writes a structured request, the host application executes the tool, and the tool's output returns to the model as text in the same context as the user's instructions (the root of the prompt-injection problem discussed in Section 5.6).
- **caption:** Figure 5.2: A single tool call. The model never runs the tool itself: it emits a structured request, the host application executes it, and the result returns to the model as new input. That returned text sits in the same context as the user's instructions, which is why untrusted tool output matters for security (Section 5.6). Schematic by the author, after [@openai2023function; @modelcontextprotocol2026tools; @greshake2023not].
- **content:**
  - Layout: classic sequence diagram, four vertical lifelines left → right: "User", "Application", "Language model", "Weather tool". Time runs top → bottom.
  - Messages (horizontal arrows, numbered):
    1. User → Application: "Weather in Leeds?"
    2. Application → Language model: "Question + tool list"
    3. Language model → Application: "get_weather(location: Leeds)" (render in monospace, inside a small box marked "structured request"; one argument, matching the get_weather schema in the chapter's JSON example)
    4. Application → Weather tool: "Run get_weather"
    5. Weather tool → Application: "Forecast data"
    6. Application → Language model: "Tool result as text"
    7. Language model → Application: "Final answer"
    8. Application → User: "Answer shown"
  - Annotation bracket on the Application lifeline spanning messages 3–5: "Holds permissions; decides whether to run".
  - Annotation (shaded note) beside message 6: "Tool output enters same context as instructions".
  - Labels of messages 4 and 5 sit between the Application and Language model lifelines so they do not cross the model's lifeline.
  - Greyscale; dashed arrows for returns (5, 7, 8), solid for requests.
