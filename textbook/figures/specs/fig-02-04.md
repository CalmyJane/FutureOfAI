# Figure 2.4: Residual connections

- **type:** diagram + bar chart (two panels side by side)
- **purpose:** Show what a residual block is (the shortcut that adds the input back) and the evidence that made it matter: without shortcuts a deeper network did worse than a shallower one; with shortcuts the deeper network did better.
- **caption:** Figure 2.4: Residual connections. (a) A residual block: the input *x* passes through two weight layers to give *F*(*x*), and a shortcut adds the unchanged input back, so the block outputs *F*(*x*) + *x*. (b) Top-1 error on the ImageNet validation set: a plain 34-layer network does worse than a plain 18-layer one (28.54% against 27.94%), while with residual connections the deeper network does better (25.03% against 27.88%). Source: @he2016deep.
- **content:**
  - **Panel (a), diagram, top → bottom** (after He et al. 2016, Fig. 2):
    - Input arrow at top labelled "x".
    - Box "weight layer", then label "ReLU", then box "weight layer"; the output of this path labelled "F(x)".
    - A curved arrow from the input "x" bypassing both boxes on the right, labelled "shortcut (identity)".
    - Circle with "+" where the two paths meet; label "F(x) + x".
    - Then label "ReLU" and output arrow at the bottom.
  - **Panel (b), grouped bar chart:**
    - y-axis: "Top-1 error (%)", linear, range 24 to 30 (axis break or start at 24 clearly marked; alternatively 0 to 30 with value labels).
    - Two groups on the x-axis: "Plain network" and "Residual network (ResNet)".
    - In each group two bars: "18 layers" (lighter grey) and "34 layers" (darker grey).
    - Values: Plain 18 layers 27.94; Plain 34 layers 28.54; ResNet 18 layers 27.88; ResNet 34 layers 25.03. Print each value above its bar.
    - Small annotation over the plain group: "deeper is worse"; over the residual group: "deeper is better".
    - Data source: He et al. 2016, Table 2 (top-1 error, %, 10-crop testing, ImageNet validation; the ResNets have no extra parameters compared with the plain networks) [he2016deep].
  - Greyscale-friendly.
